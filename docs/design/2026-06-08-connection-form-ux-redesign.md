# 연결 설정 화면 UX 개선 제안

작성일: 2026-06-08
대상: JMTerm — `새 SSH 연결` / `서버 수정` 다이얼로그
관련 코드: `Sources/JMTerm/Views/ConnectionFormView.swift`, `ConnectionDialogView.swift`, `EditConnectionView.swift`

> 목표: 초보자도 쉽게, 개발자·서버 관리자도 빠르게 입력할 수 있는 UX.
> SSH·SFTP·Jump Host(Bastion)·SSH Key 인증을 자주 쓰는 사용자를 고려하고,
> macOS 다크 테마를 유지하며 Termius·SecureCRT·Tabby·Royal TS 수준의 사용성을 지향.

---

## 1. 현재 화면 (As-Is)

```
새 SSH 연결
   이름   [ (focus, 빈칸) ............ ]
   호스트 [ .......................... ]
   포트   [ 22 ...................... ]
   사용자 [ .......................... ]
          ☐ SSH 키 사용
   비밀번호[ .......................... ]
   점프 호스트 경유 (선택)
   ┌ 경유 없이 직접 연결합니다.
   └ ⊕ 점프 호스트 추가
   ──────────────────────────────
   [테스트 연결(비활성)]
                    ☑ 연결 정보 저장
                         [취소] [연결]
```

**한 줄 진단:** 기능은 충분하나 *정보 구조*가 역순이고, 인증 방식이 모호하며,
필수/선택 구분과 액션 버튼 위계가 약하다.

## 2. 정보 구조(IA) 평가

| 항목 | 현재 | 문제 | 평가 |
|---|---|---|---|
| 입력 순서 | 이름 → 호스트 → 포트 → 사용자 → 인증 | 이름이 맨 위 + 첫 포커스. 이름은 host/user에서 파생되는데 가장 먼저 요구 | ❌ 역순 |
| 필수/선택 구분 | 시각적 구분 없음 | host·user는 필수, 이름·비밀번호는 선택인데 동일하게 보임 | ❌ |
| 인증 위치 | "SSH 키 사용" 체크박스가 사용자와 비밀번호 사이 | 인증은 "모드 전환"인데 일반 체크박스로 표현 → 키↔비번 필드가 슬쩍 바뀜 | ⚠️ |
| 점프 호스트 | 별도 박스 + "(선택)" 명시 | 위치·라벨은 좋음. 용어 설명 부재 | 🟡 |
| 포트 | 기본값 22 | 좋음. 대부분 22 고정이라 상단 상시 노출은 자리 낭비 | ⚠️ |
| SFTP | 언급 없음 | 앱은 SSH+SFTP인데 다이얼로그는 SSH만. 좌측 파일 탭 자동 연동이 안 보임 | 🟡 |

**초보자 난점**
- "이름"이 뭘 적는 칸인지 모름(별명인데 빈칸+포커스라 필수처럼 보임).
- "SSH 키 사용"을 켜야 할지 판단 불가(기본 비밀번호 흐름은 다행히 직관적).
- "점프 호스트" 용어 자체를 모름(게이트웨이/배스천 설명 필요).

**전문가 난점**
- host/port/user를 3칸 따로 입력 → `user@host:22` 한 줄 빠른 입력 불가.
- 키 인증 시 키 파일을 경로 텍스트로만 입력 — `~/.ssh` 자동 탐지/목록 선택 없음.

## 3. UX 문제점

**3-1. 입력 마찰**
- 첫 포커스가 이름(비핵심) → 핵심인 호스트여야 함.
- "테스트 연결"이 비활성인데 이유 미표시(host+user+비번/키가 다 차야 활성).
  초보자는 회색 버튼만 보고 "왜 안 눌리지?"를 느낌.

**3-2. 시각적 계층**
- 모든 필드가 동일 굵기·높이 → 중요도 신호 없음.
- 라벨은 우측정렬인데 "SSH 키 사용" 체크박스만 라벨 컬럼을 벗어나 그리드가 깨짐.
- 구분선 1개로 폼/액션을 나눴으나 "테스트 연결 / 저장 / 취소 / 연결"이 3층으로
  흩어져 시선이 분산.

**3-3. 버튼 배치**
- 주 액션 `연결`(우하단 accent) = macOS 관례 ✅.
- 그러나 `테스트 연결`이 폼과 액션 사이 좌측에 떠 소속이 모호. "연결 정보 저장"
  체크가 액션 영역에 끼어 위계 혼란.

**3-4. SSH 키 이해도**
- 체크박스 ON → 비밀번호 칸이 키 경로 칸으로 교체. "키 + passphrase" 복합
  케이스 표현 불가. 키 파일이 경로 문자열 의존이라 오타·혼동 위험.

**3-5. 점프 호스트 이해도**
- 접힘 구조·"(선택)"은 좋음. 펼치면 내부에 host/user/인증이 한 벌 더 들어오는데,
  메인 서버와 시각적 구분이 약하면 "지금 어느 서버 입력 중?" 혼란. 단계 라벨 필요.

## 4. UI 개선안

**4-1. 필드 재배치(입력 순서 정상화)**
`호스트 → 포트 → 사용자 → 인증 → (고급) → 이름(자동/선택)`
이름은 맨 아래로, placeholder에 자동값(`user@host`) 노출, 비우면 자동 생성.

**4-2. 섹션 분리**
`일반(서버)` / `인증` / `고급(접기)` 3개 그룹박스(시스템 설정·Termius식 카드).

**4-3. 접기/펼치기(Progressive Disclosure)**
- 기본 노출: 호스트·사용자·인증.
- 기본 접힘: 고급(포트·KeepAlive·압축·Agent Forwarding), 점프 호스트.
- → 초보자는 짧은 폼, 전문가는 펼쳐서 풀세팅.

**4-4. Placeholder 개선**

| 필드 | 현재 | 개선 |
|---|---|---|
| 호스트 | (빈칸) | `예: 192.168.0.10 또는 server.example.com` |
| 사용자 | (빈칸) | `예: ubuntu, root` |
| 이름 | (빈칸) | `비우면 자동: user@host` |
| 키 경로 | `~/.ssh/id_ed25519` | 목록 드롭다운 + `찾아보기…` |
| 점프 host | — | `게이트웨이 호스트 (공인 IP:22)` |

**4-5. 도움말 문구(ⓘ/툴팁)**
- 인증: "키 인증은 비밀번호 없이 안전하게 접속합니다."
- 점프 호스트: "내부망 서버 앞의 게이트웨이(배스천)를 거쳐 접속합니다.
  좌측 파일 탐색기도 최종 서버를 가리킵니다."
- 테스트 연결 비활성 시 캡션: "호스트·사용자를 입력하면 테스트할 수 있어요."

## 5. 전문 SSH 클라이언트 관점

| 기능 | 현재 | 개선 |
|---|---|---|
| 이름 자동 생성 | 빈칸이면 `user@host`(코드엔 있으나 비가시) | placeholder로 명시 + 라이브 미리보기 |
| 빠른 입력 | host/port/user 3칸 | 상단에 `user@host:port` 한 줄 퀵필드 → 파싱해 자동 분해 |
| 최근/알려진 호스트 | 없음 | host 입력 시 known_hosts·기존 연결 자동완성 |
| 인증 방식 선택 | 체크박스(비번↔키 토글) | 세그먼트 `비밀번호 / SSH 키 / SSH Agent` + 조건부 필드 |
| SSH 키 | 경로 텍스트 | `~/.ssh` 키 자동 탐지 드롭다운 + 찾아보기 + passphrase 필드 |
| 테스트 연결 | 비활성 이유 불명, 결과 협소 | 활성 조건 캡션 + 인라인 결과(성공/실패/소요시간), 체인 전체 검증 |
| 고급 | 포트만 | KeepAlive 간격 · Compression · Agent Forwarding · 터미널 타입 — 접힘 그룹 |

## 6. 시각 디자인

- **여백**: 그룹 간 16pt, 필드 간 10pt, 그룹 내부 패딩 12pt로 통일.
- **입력창 높이**: 28→32pt, 코너 6pt(클릭 타겟 ↑).
- **폰트**: 라벨 13pt regular, 섹션 헤더 11pt uppercase secondary, 입력 13pt.
- **라벨 정렬**: 우측정렬 유지하되 체크박스/세그먼트도 같은 그리드에 정렬(깨짐 제거).
- **버튼 우선순위**: `연결`=accent filled, `취소`=plain, `테스트 연결`=bordered(보조)로
  격하해 주 액션과 명확히 구분.
- **다크 컬러 토큰(예시)**

  | 토큰 | 값 | 용도 |
  |---|---|---|
  | bg.surface | `#1C1C1E` | 카드 배경 |
  | bg.field | `#2C2C2E` | 입력창 |
  | border | `#3A3A3C` | 테두리 |
  | text.primary | `#FFFFFF` | 본문 |
  | text.secondary | `#98989F` | 라벨/힌트 |
  | accent | `#0A84FF` | 주 액션(연결) |
  | success | `#30D158` | 테스트 성공 |
  | danger | `#FF453A` | 오류 |

- **아이콘(SF Symbols, 라벨 leading)**: 호스트 `network`, 사용자 `person`,
  비밀번호 `lock`, 키 `key.fill`, 점프 `arrow.triangle.branch`, 테스트 `bolt.horizontal`.

## 8. 가장 추천하는 최종 UI 구조 (이유)

> **점진적 노출(Progressive Disclosure) 3단 구조** — 서버 → 인증 → (접힘)
> 고급/점프, 이름은 자동화.

```
[ 빠른 입력 ]  user@host:port   (선택, 전문가 가속)
[ 서버 ]       호스트* · 사용자*
[ 인증 ]       세그먼트(비밀번호/키/Agent) + 조건부 필드
[ ▸ 점프 호스트 ]  (접힘, 선택)
[ ▸ 고급 설정 ]    (접힘, 포트·KeepAlive·압축·Forwarding)
[ 이름 ]       자동 생성(맨 아래, 선택)
[ ☑저장 ]  [⚡테스트]      [취소][연결]
```

**왜 이 구조인가**

1. **초보자**: 보이는 필수 칸이 호스트·사용자·(비밀번호) 3개뿐 → 인지 부하 최소.
   어려운 점프/고급은 접혀 있어 "안 보이면 안 써도 된다".
2. **전문가**: 상단 퀵필드 한 줄로 `user@host:22` 즉시 입력 + 점프/고급 펼쳐 풀세팅.
3. **올바른 순서**: 서버 → 인증 → 부가 → 이름(파생). 이름을 마지막+자동으로 빼
   "빈 이름 칸이 길을 막는" 현재 문제 해소.
4. **필수/선택 명확화**: `*` 표기 + "(선택)" 라벨 + placeholder 힌트.
5. **인증 세그먼트**: 토글이 아닌 명시적 모드 선택 → 망설임을 선택지로 전환,
   passphrase 같은 복합 케이스 수용.
6. **버튼 위계 정리**: `연결`(accent) 단독 강조, `테스트`는 bordered 보조,
   `저장` 체크는 좌측 정렬 → 시선이 우하단 주 액션으로 자연 수렴.
7. **점프 단계 라벨 + 들여쓰기**: "지금 게이트웨이 입력 중"이 시각적으로 분명 →
   배스천 경유의 핵심 혼란 제거.

## 9. 구현 로드맵 (우선순위 · 코드 매핑)

현재 코드 구조와 100% 호환 범위 기준.

**🥇 1순위 — 즉효·저비용** (`ConnectionFormView`, `ConnectionDialogView`)
- 입력 순서 변경(이름 맨 아래), 첫 포커스 호스트(`@FocusState`).
- placeholder/도움말 문구, 필수 `*` 표기.
- 인증을 체크박스 → `Picker(.segmented)` 비밀번호/SSH 키.
- 테스트 연결 비활성 사유 캡션.
- 버튼 위계(`테스트`=`.bordered`, `연결`=`.borderedProminent`).

**🥈 2순위 — 중간**
- 점프 호스트 행에 단계 라벨("1단계 · 게이트웨이")·들여쓰기 강화(`JumpHostRowView`).
- SSH 키 `~/.ssh` 자동 탐지 드롭다운(`FileManager`로 디렉토리 스캔).
- 테스트 결과 표시 강화(소요시간/실패 사유).

**🥉 3순위 — 고급**
- 상단 `user@host:port` 퀵필드 파싱.
- 고급 설정 섹션(KeepAlive·Compression·Agent Forwarding·터미널 타입) —
  모델(`ServerConnection`) 필드 추가 + `SSHSession` 반영 필요.
- 최근/알려진 호스트 자동완성.

**참고**: 3순위의 KeepAlive/Compression/Agent Forwarding은 Citadel(SSH 라이브러리)
지원 범위 확인이 선행되어야 하며, `ServerConnection` 스키마 확장 시 기존 점프 호스트와
동일하게 하위호환 디코딩(`decodeIfPresent`)을 적용해야 한다.
